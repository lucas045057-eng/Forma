# Lux3D 站内创作与网页放置增量设计

状态：用户已选择“拖入后点一次生成模型”，认可站内简洁主流程与网页拖入交互，并授权按既有角色开始增量设计开发。Codex负责本设计与集成；CodeBuddy实现；Pi独立验收；Claude独立审查。

## 目标与交互

主流程为：拖入图片（也可点选文件）→预览图片→点一次“生成模型”→等待任务→旋转查看结果→拖到网页或点“放入网页”→确认采用。拖入、选参数、切页、刷新不创建付费任务。

默认面板只暴露图片、可选描述、生成按钮、进度与结果卡。高级工具折叠；任务历史长期可恢复。现有本地备用和已有任务导入保留为次级入口，用户无需复制URL或任务编号才能完成新流程。

结果卡必须在放置期间仍可见：将现有阻挡网页的资产对话框改成可收起侧栏/抽屉；不要让用户拖拽时网页被遮住。卡片显示缩略图、实际来源、状态与必要错误。所有拖放均有按钮/键盘替代入口。

## 方案选择

采用“简洁主流程＋完整高级工具”。完整功能平铺会干扰普通使用；嵌入第三方网页无法可靠贯通鉴权、资产、采用和撤回，因此不采用。不是只给旧API加按钮，也不以第三方网页跳转代替站内能力。

## 后端契约

新增独立职责模块，优先保留已有AssetService稳定接口：

1. 上传接收本地文件，存储opaque uploadId；浏览器不拿云凭据。图片仅PNG/JPEG/WebP，单张最大10MiB、最大4096万像素；实际解码校验，不相信扩展名/MIME；拒绝SVG/HTML和压缩炸弹。多图按官方上限1–32张有序处理；本地GLB限制100MiB并验结构。每请求/总体大小与超时显式受限，不全局放大Fastify限制。
2. 官方Asset上传凭证及OUS上传由后端完成；API key与上传凭证不进入公开配置/日志/事件。只允许服务配置及可信凭证给出的上传目的域，不提供通用URL代理；拒绝localhost/私网/重定向绕过/任意路径；远端产物下载复用并加强既有安全边界。
3. 规范化操作模型：`LuxOperation`覆盖上表10项；`LuxTask`包含localId、operation、providerTaskId字符串、阶段、输入引用、参数指纹、产物列表、错误和时间。云端int64 ID须无损解析，不先JSON number后转string。`LuxArtifact`明确kind=image/model/archive、格式、来源、哈希、可用本地assetId。
4. 建议本地路由 `/assets/uploads`（上传）、`/assets/lux3d/capabilities`（无密钥）、`/assets/lux3d/operations`（创建）、`/assets/lux3d/tasks`（历史）、`/assets/lux3d/tasks/:id`（状态）、`/assets/lux3d/tasks/:id/resume`（只查询恢复）。保持旧 `/assets/lux3d` 与import路由兼容；新浏览器传opaque引用，不传任意云URL。路径可按现有约定合理收敛，报告准确记录。
5. 客户端一次明确提交带幂等键；服务在云POST前持久化原子占位和参数指纹。同键同参数返回原任务，同键异参409；双击、刷新、重连及超时不二次付费创建。已明确业务拒绝与提交结果未知分开；未知状态保留待核实，先查原任务/历史，不自动重发。
6. 任务持久化、重启恢复、受控轮询、有限查询重试。失败不能显示100%；未知进度用阶段/不定进度；服务关闭中不接受新任务。若无官方远端取消接口，仅停止本地等待并说明远端可能仍运行，不能声称退款或取消成功。
7. 创建按钮前展示服务费用/计费提示；若配置支持报价，报价与本次参数绑定，不把失败报价当0。用户点击明确创建才提交。开发/自动化只用fake上游，实际付费验收由根统一安排，不在本批开发调用。

## 网页放置协议

- 只允许ready、本地校验通过且可渲染的GLB模型拖放。拖拽内容使用内部assetId和短期drag会话标识，不能接受任意文件路径、URL、HTML、源码或外来DataTransfer。
- Studio启用放置会话，绑定资产、当前作品版本、主预览iframe及有效期。iframe返回命中目标、目标类型、源码身份和位置；父侧严格核对origin/source、消息schema、会话/版本。候选/对照frame不得当主作品目标；越界、旧会话、未知目标拒绝。
- 高亮显示“替换此3D模型”或“在此添加3D模块”；落下后进入确认预览，未确认不写主作品、不发编码任务。键盘“放入网页”可进入同一目标选择与确认流程。
- 已有3D主槽位：复用scene采用、字节来源验证与history，确认后更新，撤回恢复场景及来源；网页门槛不自动force。既有单槽配置兼容。
- 普通区域：生成带受信资产引用与确定插入锚点的候选任务；原模型文件/metadata通过受控路径放进候选。用户可以查看差异，原请示、检查、采用门禁全部保留。禁止拖完直接改主作品或拼接执行任意页面源码。
- 新增模块要使用独立模型引用和实例配置，不共享全局SceneConfig.model造成所有模块一起变化；提供对应大小/角度/位置调整入口。位置采用目标容器内布局/插入前后语义，不能把浏览器viewport绝对坐标当永久CSS。
- 新模块资产必须包含在候选检查、采用和回退范围；明确多实例来源、被删除资产的引用和候选取消清理。不得为此破坏原M1-B单槽视觉/撤回合同。
