# 空间化工作台演示手册（开发交付，尚未彩排）

本手册与启动脚本已经编写，但本轮没有启动服务、运行彩排或调用真实模型。先完成集中测试与独立审查，再执行演示。当前从既有香薰模板开始，不宣称能导入任意网站或自动生成通用初版。

## 两种入口

从本工作树根目录运行，依赖必须已经按锁文件安装；脚本不安装、不下载、不修改锁。

```text
node scripts/demo/mock.mjs
node scripts/demo/real.mjs --allow-real-services
```

以上只是操作说明，本次开发没有执行。禁止改用 pnpm dev / server dev 或 --env-file：它们可能加载真实配置。父进程 NODE_OPTIONS 和额外 Node loader 参数必须为空；子进程环境由代码白名单重建，不继承代理、loader、GIT_DIR 等注入。不要在命令行参数里放任何密钥。

每次入口生成新的 `.data/demo-runs/<UTC>-<UUID>/`，保留 manifest.json、plan.json、白名单模板副本、源文件SHA、隔离资产/作品版本库/场景历史/缓存及进程记录；不会reset、clean、删除旧作品或旧run。仅Git已跟踪的src/public文件和固定根文件才可复制，.env、证书、备份、缓存与链接不复制；node_modules只链接当前锁定工作区依赖。若文件路径/依赖/端口检查失败，保留未完成run并退出，不重用旧产物。

终端就绪后会打印该轮实际本机Studio地址，7个端口均取20000以上的独立随机值，冲突或Windows保留端口导致启动失败时不杀占用者；重新开一次会生成另一个run。客户端进入Studio后仍要等待连接/同步就绪，不能靠启动成功推定检查或候选已通过。

### mock

编码、Lux3D、阿里协议转写全部是本机模拟上游，后端只允许127.0.0.1 HTTP端点。**独立出站守卫只预加载在backend和frontends两个主进程**：这两个进程的非本机DNS/连接/fetch被拒，纯IP lookup仅走本地解析。资产处理worker、候选预览worker和检查worker没有加载该守卫；它们按各自合同只处理本地文件/本机服务，但不能据此声称整个进程树被强制离线。录音仍需用户明确按住；返回的转写固定为“把购买区向下移动一点”，不是识别真实语义。Studio和review持续标注模拟；浏览器厂商识别在离线模式禁用，不能暗中联网兜底。

编码模拟仅支持三条固定示例：购买区下移、标题改动、共享按钮圆角。它仍调用真实候选文件工具，仍需请示、真实检查与采用；不支持的指令安全结束为无改动，不伪装通用编码模型。Lux3D模拟不计费，也不能称现场生成；三维演示优先使用作品自带模型与固定本地备用目录，避免把模拟远端返回的简化模型当成真实生成质量。模拟远端资产来源记unknown，不跨模式冒称真实Lux3D来源。

### real：阿里云百炼为正式语音主链

本入口只接受操作者提供的进程环境，不读取任何既有.env文件。原有本地配置可由操作者私密环境管理器注入，但不能复制到报告、前端或命令参数中。`scripts/demo/real.env.example`只说明变量名和占位符，脚本不会加载它。

| 后端变量 | 约束 |
| --- | --- |
| DASHSCOPE_API_KEY | 操作者私密提供的百炼key，不借用编码模型key |
| SPEECH_BASE_URL | 完整compatible base，例如 https://dashscope.aliyuncs.com/compatible-mode/v1 |
| SPEECH_MODEL | qwen3-asr-flash（固定支持值） |
| CODING_AGENT_BASE_URL / API_KEY / MODEL | 本轮已授权的HTTPS兼容编码服务配置，可缺省而安全失败 |
| LUX3D_BASE / LUX3D_API_KEY | 已授权的HTTPS Lux3D配置；无生成授权时只使用本地备用 |

语音端点必须HTTPS/default443、固定/compatible-mode/v1路径、无userinfo/query/hash。主机只接受dashscope.aliyuncs.com、dashscope-intl.aliyuncs.com，或设计规定的业务空间形式 `<workspace>.(cn-beijing|ap-southeast-1).maas.aliyuncs.com`；不是任意aliyuncs后缀，不能填OSS桶。地域、业务空间与key必须匹配。首次真实调用仍需核对请求Data URI和返回文字协议、实际质量/延迟；当前没有该证据。

语音配置非法会令整个后端快速失败，不会静默切换厂商；只在后端私密检查变量名、地域、模型和路径，不打印密钥/完整错误上游body。35秒预算从上游请求开始，**不含上传**；前端录音60秒/4MiB、转写等待45秒。取消按SPEECH_CANCELLED处理（可能HTTP499），取消/断网不保证未计费。每次重试重新录音并用新UUID；不自动重发缓存失败请求。

启动real前另行确认本轮调用范围/预算，例如语音段数__、编码任务__、每任务最多轮数__、Lux3D生成0或明确__。`--allow-real-services`只防误启动，不能代替具体付费授权。脚本不自动POST任何付费任务；实际用户点击才可能调用上游。没有授权或配置时留mock/文字/本地备用，不把替身算真实成功。

## Lux3D 新链路：上传 → 生成 → 放入网页（未彩排）

本节覆盖增量新增的站内创作与网页放置，替代上面「五分钟脚本」中仅有的编辑演示；上面那条时间轴属于 M4 旧链路，仍可按原样演练，但**不能**用它证明新链路。本节按产品 `037eda1` 的真实 UI 文案编写，未执行、未彩排；任何一步的“通过”只以实际观察和日志为准。

### 前提与启动

- 只从开发启动进入：`node scripts/demo/mock.mjs`（全本机替身，不联网）或既有 demo 启动器并打印本轮 Studio 地址；新链路目前没有独立 `start-demo.cmd`，旧发行包里的启动脚本早于本增量，**不保证**支持。
- 端口（开发）：backend `3001`、Studio `5173`、模板预览 `5174`、preview origin `5175`，均 `127.0.0.1`；演示启动器改用 20000–65535 的随机端口，以终端打印地址为准。
- 依赖必须已按锁文件安装；不改锁、不安装、不下载。浏览器需预装 Chromium（检查中的「页面冒烟」依赖它）。
- 凭据只由操作者在后端进程环境提供（`LUX3D_BASE`/`LUX3D_API_KEY`，可选 `LUX3D_UPLOAD_HOSTS`）；本文不展示任何值，也不用命令行参数传密钥。

### 主流程（按界面文案）

1. **上传或选输入**：Studio 的 Lux3D 工作台，把图片/GLB 拖到「把图片或 GLB 拖到这里，也可以选择文件」，或选择已有上传。界面会明确「拖入只会本地暂存，不会上传云端或计费」。
2. **选操作**：工具下拉共 10 类——图生3D、文生3D、多模态生图、四视图、材质迁移、部件拆分、多格式导出、关节化与动画、数字人绑骨、动画重定向。图/文生 3D 必须勾选输出格式 `glb`，否则提示「主流程需要在输出格式中勾选 glb，才能把模型放入网页」。
3. **点一次创建**：按钮是「生成模型」（图生3D）或「创建…任务」。页面固定提示「点击创建会把输入上传到云端并提交一次可能计费的任务；拖入、选参数和刷新都不会创建任务」。不要连点，切换参数后需要重新确认再点。
4. **看任务状态**：已登记，等待本地处理 → 上传到云端 → 提交中 → 处理中 → 可查看/失败；结果未知时显示「结果待核实（不会自动重提）」。历史在「创作历史」，可「下载 X 原件」。
5. **放入网页**：结果卡点「放入网页」，打开「将模型放入网页」。可拖动卡片到作品，也可点选目标；目标文案为「替换主 3D 槽位」「在此添加独立 3D 模块」「替换实例 …abcd 的模型」。确认前主作品不变。
6. **确认放置**：点「确认放置」。超过网页门槛时必须勾选「该模型超过网页门槛；我明确要求强制采用」，否则不能用 force 绕过。
7. **审批（仅独立模块/移除分支）**：审批卡「批准本次修改」/「拒绝并丢弃」，等待中可「取消任务」。批准只发布草稿，不改变主作品。
8. **四项检查**：候选面板「运行检查」，显示 场景配置 / 构建 / 页面冒烟 / 交互遮挡；六份必需证据可读且 hash 核对后，采用按钮才可用。
9. **采用**：「采用此候选」。失败或证据不完整时按钮禁用并给出原因，不绕过。
10. **撤回/调整/移除**：
    - 主槽替换：「回退上一次采用」；
    - 独立实例：「调整网页独立 3D 实例」→「保存模块调整」立即写入，可「撤回该实例上一次调整」；「创建移除候选」仍需审批+检查+采用；
    - 候选放弃：「撤回候选」。

### 放置会话 120 秒

服务端会话固定 120 秒（`apps/server/src/assets/placement.ts:174`）；过期确认返回 `PLACEMENT_EXPIRED`，界面提示「放置会话已过期，请重新放入」。过期后在结果卡上主动 hover/focus/click 会重新准备一次（App 层最多一次有界刷新），**没有后台续期**。OS 拖拽必须在有效期内完成准备，不要在过期后硬拖。

## 备用、来源与常见失败

- 本地目录只接受代码内三个preset，对应现有lux3d-split-4969889.glb、lux3d-4969293.glb、lux3d-4969298.glb。素材保持未入库，可用性由服务安全读取决定；缺失时按钮禁用，不下载补造。
- 默认sidecar依据M1-A-impl“默认资产”与M1-fix-impl的处理记录，绑定当前GLB真实hash；没有填生成时间或未经核对的上游任务链。更换数据目录/回退后从作品sidecar重读，不依赖旧asset index。
- 来源missing/损坏/hash不同就显示未核实；同名不同内容或不同来源拒绝覆盖。跨处理版本产物是否字节确定尚未运行验证，保留ASSET_NAME_CONFLICT，不用force绕过。
- 断线/状态待同步先只读刷新；未知POST结果不自动重发。STALE_SELECTION需重新点选，STALE_CANDIDATE需重新生成；采用失败不靠旧绿灯强行继续。
- 权限等待、录音、转写仍在失焦/隐藏/门禁关闭时立即取消；已经完成的review在iframe点选、短暂重连、任务锁或场景面板hidden期间保留但不能确认，ready后必须明确确认新对象。document真正隐藏或卸载会明确放弃review。语音任务POST确认成功才解除旧绑定；失败或未知结果仍保守保持，手动放弃旧绑定不会清掉后来新输入的文字。
- 本地处理/预览/检查失败显示真实失败或未运行，不把缺浏览器、取消或服务错误叫作页面通过。

## 停止与恢复

在父启动终端Ctrl+C，父进程按自有ChildProcess/IPC通知frontend和backend正常关闭并等待；只在其仍在途且超有界预算时终止自己持有的进程句柄，标记cleanup_failed/forced，不广杀同端口/同名进程。模型子进程/预览worker沿原生命周期退出；所有run与中断现场保留。

manifest记录角色/PID/启动时间/退出码或信号/强制退出与清理问题；它不是成功彩排结论。子进程收到控制台信号时先向父进程报告关闭意图，正常关闭不应因父子收信号先后而误记interrupted；非零退出、强杀或清理失败仍为失败。只有进程仍能执行并实际收到IPC disconnect事件时，才会进入正常close及watchdog路径。生产代码设置50秒预算，超期后按本进程父子链及PID/创建时间核对并结束自有后代，最多三次各5秒的身份扫描，写独立`orphan-cleanup-<pid>.json`并exit1；这是代码策略，不是硬杀父进程后一定执行的保证。已运行的watchdog证据来自fixture角色主动断开IPC且close挂起的控制分支，使用测试专用缩短预算，不代表生产50秒路径已实测。OS身份查询失败会明确记录，不能承诺已清干净。

本机硬杀对照观察到整个原测试进程链在fallback之前消失，但中间角色没有disconnect/close-called/exit记录，也没有watchdog回收清单。因此只能记“进程链退出且未补杀”，不能记“IPC处理或watchdog自主回收”。宿主或操作系统直接终止进程链是机制解释，现有记录没有单独定位其具体实现，不能泛化为所有Windows或所有杀进程方式。其他已知限制：中间父进程先退出时，按当前父子关系遍历可能漏掉孙进程；正常Ctrl+C超过45秒后启动器强杀直接子进程，也不能保证先执行watchdog。各worker的disconnect处理只有在其实际收到事件且仍能执行时才可能生效。两类路径都须核真实后代与端口，不能仅凭存在退出处理代码就承诺已回收，也不按名称广杀。

证据用语详见[清理证据边界](../reports/M4-cleanup-evidence-boundary.md)。资产夹具的历史`autonomousWorkerExit`字段只表示“测试未fallback杀worker而观察到原身份已消失”，不证明退出由IPC处理器造成；Pi硬杀场景同样只记录实际退出，不能把它写成已证明IPC机制。原JSON和日志保持原样，说明层更正含义。

不要凭“父进程退出”说没有后代，集中验证须核backend/frontends、预览/检查/Chromium/资产worker及其后代的真实PID创建时间与端口，包括中间层先死、正常关闭挂起后的45秒强杀、OS强杀和Windows真实Ctrl+C。现有资产父死实现测试使用专用父夹具而非生产process-isolated启动接线，且依赖Windows PowerShell CIM；真实demo处理split GLB期间硬杀后端、重启持锁清理staging的路径仍需另以集中实测证明，不代表跨OS覆盖。

索引保存失败（包括Windows临时文件占用导致的EPERM/EBUSY）会粘性保留jobFailure：idle/close报错、实例锁保留，本轮可能记cleanup_failed。先保留run和安全错误码，核对实际自有PID/创建时间/端口；等待原进程退出后由现有死进程锁恢复逻辑接管，必要时人工检查目录占用，不在进程仍活着时删除锁、不自动重复提交未知结果。不要手工清零错误或为了演示伪造stopped；需要重试演示时新建run，保留原失败现场，不删除其它Agent工作树或重置用户作品。
